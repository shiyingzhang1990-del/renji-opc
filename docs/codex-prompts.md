# Codex 分阶段开发提示词

不要一次让 Codex “完成淘宝级平台”。每次只交付一个可测试模块，
要求它先阅读现有仓库、生成迁移、补测试、运行测试并汇报变更。

## Prompt 1：登录、用户和权限

```text
你正在维护 renji-opc-mvp 仓库。请先完整阅读 README、docs 和 backend/app。
在不破坏现有 API 的前提下，实现用户、角色和权限系统。

角色包括：
buyer、merchant_owner、merchant_staff、community_operator、
platform_operator、risk_reviewer、dispute_mediator、super_admin。

要求：
- JWT 短期访问令牌 + 可撤销刷新令牌
- 密码安全哈希
- RBAC
- 所有写接口鉴权
- 多租户数据隔离
- 数据库迁移
- pytest
- 日志不得输出密码、Token 或身份证件信息
完成后运行测试，并列出修改文件。
```

## Prompt 2：商家入驻与认证

```text
实现 OPC 商家入驻流程：
draft → submitted → reviewing → verified / rejected → suspended → exited。

字段包括公司名称、统一社会信用代码、负责人、联系方式、注册地址、
所属社区、行业分类、专业资质、案例、收款主体标识、风险等级和复核日期。

要求：
- 文件只保存对象存储 key
- 敏感字段加密或脱敏
- 审核写入不可修改审计日志
- 支持平台审核与社区初审
- 认证后才能发布商品
- API、测试和后台页面
```

## Prompt 3：商品中心

```text
商品必须同时关联业务品类和交付类型。
交付类型包括 digital_good、subscription、fixed_service、
milestone_project、hourly_consulting、api_resource、physical_or_hybrid。

字段包括服务对象、客户问题、服务范围、不包含内容、交付物、周期、
价格、报价方式、验收标准、修改次数、知识产权、保密、数据处理、
AI 生成内容声明、售后、退款和 SLA。

实现草稿、审核、发布、驳回、下架、版本和订单快照，并补测试。
```

## Prompt 4：真实支付适配器

```text
不要自行设计钱包或资金池。在现有 PaymentProvider 接口下，
基于支付机构官方最新文档实现平台型支付适配器骨架。

要求：
- 商家/二级商户进件映射
- 支付下单
- 异步通知验签
- 幂等
- 金额校验
- 分账/解冻
- 退款
- 分账回退
- 日终对账
- 密钥从环境变量或密钥管理系统读取
- 未配置真实参数时安全失败，不能伪造成功
- sandbox/mock 集成测试
```

## Prompt 5：里程碑履约和争议

```text
增强里程碑订单：交付物、验收、驳回、修改次数、变更单、
自动验收倒计时、高风险订单人工复核、争议后停止释放、
证据材料、部分退款、部分放款、申诉和审计日志。

覆盖重复回调、重复验收和并发释放测试。
```

## Prompt 6：经营管家

```text
新增多租户 OPC 经营管理模块：
客户、线索、商机、报价、合同、项目、任务、应收、发票状态、
成本和现金流预测。

订单成交后自动创建客户、项目和应收记录。
商家只能访问本租户数据。
CSV 导出需权限与审计。
```

## Prompt 7：社区联盟

```text
每个社区拥有独立主页、Logo、城市、运营方、政策、活动、商家和商品。
社区管理员只能管理本社区。
支持社区认证徽章、招商邀请码、贡献统计和技术服务费账务记录。
分成只做账务指令，不自行划转资金。
```

## Prompt 8：上线前安全加固

```text
先给威胁模型，再加固身份认证、越权、多租户隔离、SQL 注入、XSS、
CSRF、SSRF、文件上传、回调验签、幂等、金额篡改、日志脱敏、
依赖漏洞、限流、备份恢复、审计日志和数据留存。

不得用“前端隐藏”代替服务端权限校验。
```
