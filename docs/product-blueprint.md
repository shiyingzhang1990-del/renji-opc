# 壬集 OPC 平台产品蓝图

## 一、产品定位

壬集不是单纯的“OPC 黄页”，而是四个系统的组合：

1. **OPC 服务市场**：像电商平台一样完成分类、搜索、店铺、商品、评价和交易。
2. **履约保障平台**：通过合同、里程碑、验收、争议和第三方支付结算降低交易风险。
3. **OPC 经营操作系统**：向商家提供销售、客户、项目、财务、营销、供应链和 Agent。
4. **全国社区联盟底座**：让各地 OPC 社区拥有独立节点，同时共享交易与服务网络。

## 二、为什么要做二维分类

仅按行业分类不够。壬集应同时设置：

### 1. 业务品类

- 品牌与广告设计
- 内容、短视频和数字营销
- 软件、SaaS 与 AI Agent
- 财务、税务和企业服务
- 销售、客服和 CRM
- 供应链、采购和外包
- 法律、知识产权和数据合规
- 战略、组织、风控和管理咨询
- 教育培训和知识产品
- 医疗、制造、文旅、跨境等垂直行业

### 2. 交付类型

- 即时数字商品
- 按月/按年订阅
- 固定范围标准服务
- 里程碑项目服务
- 按时计费咨询
- API、Token、算力等资源服务
- 实物与数字混合交付

交付类型决定合同模板、支付方式、验收规则、退款规则和评价指标。

## 三、核心角色

- 买家：个人、企业、政府、园区和链主企业
- OPC 商家
- OPC 社区运营方
- 专业服务商：律师、会计师、营销机构、云服务商
- 平台运营人员
- 风控与仲裁人员
- 持牌支付机构
- 第三方电子签、开票和身份核验服务商

## 四、商家入驻

1. 实名认证
2. 营业执照和统一社会信用代码
3. 法定代表人/负责人核验
4. 收款账户一致性核验
5. 行业许可和专业资质
6. 所属 OPC 社区认证
7. 代表案例、知识产权和服务能力
8. 风险等级
9. 六个月或适当周期复核
10. 退出平台后的档案留存

## 五、商品发布字段

每个商品不能只写标题和价格，至少应包含：

- 服务对象
- 客户问题
- 服务范围
- 不包含内容
- 标准交付物
- 交付周期
- 价格或报价方式
- 里程碑及金额
- 买家配合事项
- 修改次数
- 验收标准
- 知识产权归属
- 保密条款
- 数据处理方式
- 是否使用 AI 生成内容
- 售后和退款规则
- SLA
- 争议解决条款

## 六、订单与资金流程

```text
选择商品/发布需求
    ↓
商家报价或标准下单
    ↓
生成订单和合同快照
    ↓
电子签约
    ↓
买家向持牌支付机构付款
    ↓
支付机构记录待结算/冻结资金
    ↓
商家完成第 1 里程碑
    ↓
买家验收或进入自动验收倒计时
    ↓
平台向支付机构发起该阶段结算/分账指令
    ↓
支付机构向商家结算，平台收取服务费
    ↓
下一里程碑
    ↓
全部完成、开票、评价、归档
```

平台不得把客户资金直接收进普通公司账户后再人工转给商家。

## 七、里程碑状态

```text
PENDING
  → IN_PROGRESS
  → SUBMITTED
  → ACCEPTED
  → RELEASED

SUBMITTED / IN_PROGRESS
  → DISPUTED
  → 继续履约 / 部分退款 / 全额退款 / 重新交付
```

## 八、经营管理系统

### 1. 销售 CRM

- 线索
- 客户
- 商机
- 报价
- 合同
- 跟进记录
- 回款计划
- 复购提醒
- 渠道归因

### 2. 项目和履约

- 项目模板
- 任务
- 里程碑
- 文件和版本
- 客户确认
- 工时
- SLA
- 风险提示
- 变更单

### 3. 财务

- 收入
- 成本
- 应收
- 应付
- 现金流预测
- 发票
- 平台费用
- 税务提醒
- 单项目利润
- 月度经营报告

### 4. 供应链

- 外包资源池
- 供应商档案
- 比价
- 采购单
- 交付评分
- 黑白名单

### 5. 营销

- 内容日历

- 渠道账户
- 广告计划
- 私域客户
- 活动
- 获客成本
- 转化率

### 6. AI Agent 中心

- 销售助手

- 财务助手
- 合同审阅助手
- 内容运营助手
- 供应商匹配助手

Agent 只能在明确权限、日志、人工审核和数据范围内行动。

## 九、社区节点

每个城市社区应具备：

- 独立二级页面或子域名
- 社区认证徽章
- 入驻商家和商品
- 政策与补贴专区
- 本地活动和培训
- 场景需求池
- 高校和园区资源
- 城市运营数据看板
- 社区服务分成
- 社区管理员权限

## 十、平台信用体系

不要只做一个总分。建议拆成：

- 主体真实性
- 专业资质
- 准时交付率
- 一次验收通过率
- 争议率
- 退款率
- 客户复购率
- 沟通响应
- 合同和数据合规
- 社区认证
- 交易金额与持续经营时间

评分应可解释，避免简单付费买排名。

## 十一、商业模式

- 交易技术服务费
- 商家会员
- 经营管理 SaaS 订阅
- 认证服务
- 社区节点技术服务费
- 专业服务撮合佣金
- 广告与推荐位，但必须清晰标识
- 企业需求定向招标
- API、模型和算力资源差价或服务费
- 培训与加速营
- 数据洞察报告，必须合规匿名化

## 十二、MVP 边界

第一版只做：

- 8 个品类
- 3 种主要交付方式
- 商家认证
- 商品发布
- 搜索筛选
- 订单与里程碑
- 模拟支付
- 验收与争议
- 评价
- 社区节点
- 管理后台

暂不做：

- 自建支付钱包
- 自建大模型
- 复杂推荐算法
- 跨境结算
- 大规模微服务
- 自营和平台业务混在一起
